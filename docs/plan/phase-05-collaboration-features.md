# Phase 5 — 접속 승인, 클립보드, LAN 검색, 모니터·품질

## 목표

AnyDesk/RustDesk 사용자가 기대하는 편의·안전 기능을 더한다.

## 설계

- 접속 승인: 비밀번호 인증에 성공해도 호스트 사용자가 "허용"을 누르기 전에는 화면·입력을
  열지 않는 옵션 (기본 켜짐). 승인 대기 시간 제한 30초, 거부 시 `AuthResult::Rejected`.
  권한 단위: "화면 보기만" / "제어 허용"을 호스트가 선택.
- 클립보드 동기화(텍스트): `arboard`로 양쪽 클립보드를 폴링, 변경 시 `Clipboard(String)` 전송.
  되돌이 방지(받은 값을 다시 보내지 않음), 크기 상한 1 MiB, 설정에서 끌 수 있음.
- LAN 검색: `mdns-sd`로 `_open-desk._udp.local.` 서비스를 광고(기기 이름, 포트, 인증서 지문
  앞부분). 뷰어 홈 화면에 "근처 기기" 목록 표시. 광고 정보는 신뢰하지 않으며 인증은 여전히 PAKE.
- 모니터 선택: 호스트가 `DisplayList`를 보내고 뷰어가 `SelectDisplay(id)`로 전환.
- 품질 설정: 최대 해상도/FPS/비트레이트 프리셋(속도 우선, 균형, 화질 우선)을 뷰어가 요청,
  호스트가 상한 내에서 적용.

## 작업 항목

- 프로토콜 메시지 추가 (버전 호환 규칙에 따라 마이너 증가)
- 세션/호스트 서비스, UI(승인 다이얼로그, 근처 기기 목록, 모니터·품질 메뉴) 구현
- 테스트: 승인 대기/거부/시간 초과, 보기 전용 세션에서 입력 무시, 클립보드 되돌이 방지와 상한,
  모니터 전환 후 키프레임

## 완료 조건

- 위 테스트 통과, 수동으로 macOS↔Windows 클립보드 왕복 확인

## 구현 노트

- 접속 승인: 인증 직후 호스트는 `AwaitingApproval`을 보내고, 호스트 사용자가 "제어 허용 / 보기만 허용 /
  거부" 중 하나를 고를 때까지(30초 제한) 화면 캡처·입력·클립보드 어느 것도 시작하지 않는다. 대기 중
  들어온 입력은 버린다. 보기 전용 세션은 입력 스레드와 클립보드 동기화를 아예 만들지 않으며
  `HostStatus.input = NotAllowed`로 알린다. 승인/클립보드 정책은 실행 중에 바꿀 수 있고 다음 세션부터 적용된다.
- 세션이 시작되면(비밀번호 소모) 호스트 화면의 비밀번호를 지우고, 세션이 끝나면 새 비밀번호가 표시된다.
- 클립보드(텍스트): 양쪽이 250ms 간격으로 폴링하며, 세션 시작 시점에 이미 클립보드에 있던 내용은 보내지
  않는다(사생활). 받은 값은 기억해 되돌려 보내지 않는다. 1 MiB 상한, NUL 금지. 제어가 허용된 세션에서만 동작.
- LAN 검색: `_open-desk._udp.local.`로 이름·OS·인증서 지문 앞 4바이트를 광고한다. 광고 내용은 인증되지
  않은 표시용 정보로만 쓰며(이름은 검증 규칙대로 정리), 자기 자신의 광고는 지문 힌트로 제외한다.
  루프백 주소는 다른 기기에 쓸모가 없어 결과에서 뺀다(같은 기기 테스트에서만 포함).
- 모니터 전환/품질: 비디오 펌프는 세션 내내 유지하고 캡처 스트림만 다시 시작한다(새 인코더가 키프레임부터
  보냄). 입력 좌표계도 새 모니터로 바꾼다. 품질 프리셋은 호스트가 정한 상한(속도 1280px/1.5Mbps, 균형
  1920px/4Mbps, 화질 2560px/10Mbps)으로만 매핑된다.
- 헤드리스 CLI 호스트는 승인할 사람이 없으므로 비밀번호를 아는 뷰어에게 제어를 허용하고 클립보드는 끈다.
- GUI 테스트: 같은 앱 안에서 접속 폼에 자기 주소와 비밀번호를 입력해 접속 → 승인 카드 표시 → "제어 허용"
  클릭 → 세션 성립까지 실제 클릭/입력으로 검증한다.
